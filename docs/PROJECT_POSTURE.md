# Project posture — decisions about NPDev's own practices, not the product

> **Split out of `docs/ACCEPTED_BOUNDARIES.md` — REG-135 step 2, 2026-08-04.** These six rows are
> about **this repo's own CI, corpus layout, and test-coverage choices** — a fact about how NPDev is
> *developed*, never something an app author or end user can hit while building or running an app.
> Keeping them in a user-facing "what does NPDev not do" document mixed them with real product
> limits (B1, B13, B28, ...), which is a different question with a different audience.
>
> **These need no `boundaryId` and no `LIMIT` rendering** — there is no diagnostic to fire, because
> there is no user action that reaches any of them. Read `docs/ACCEPTED_BOUNDARIES.md` for the
> product's real boundaries; read this file only if you are working ON NPDev itself.
