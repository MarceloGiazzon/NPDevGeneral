**This is the third recurrence.** Main was 150 behind before T1.6, then merged; 71 behind now. The

   Run it in the knowledge gate. It needs `git fetch origin main` — cheap, and the gate is 80s with

## P3 · CLAUDE.md does not know the ledger or the declaration systems

**What.** MEASURED — mentions in `CLAUDE.md`:

```
ledger/               0      OPEN_ITEMS         0
dsl-conformance-max   0      corpusRole         0
invocation            0      DSL 2.0            0
SCREEN_TAXONOMY       0      UI_CONTRACT        0
```

**Why it matters.** CLAUDE.md is the one file an AI session actually reads before acting. Four
concrete consequences, in descending severity:

1. **A session would edit the wrong file.** `docs/NPDEV_OPEN_ITEMS_REGISTER.md` is now
   `STATUS: HISTORICAL / ARCHIVED-IN-PLACE`; `ledger/items/*.yml` is authoritative. CLAUDE.md still
   only cites the old register path (line 96 area). A session filing a finding would edit an archived
   document, and the gate would not catch it because editing history is not a contradiction.
2. **The standing DSL rule is invisible where it is needed.** *"When you add a DSL feature, add it to
   `dsl-conformance-max` in the same commit"* lives in `CONTRIBUTING.md` and the fixture's README —
   both of which an agent reads only if it thinks to. The gate enforces it *after* the work; CLAUDE.md
   is what would prevent the rework.
3. **Two declaration files are undiscoverable.** Adding any script now requires an entry in
   `script-invocation-declarations.json` (and a matching classification); adding a corpus model
   requires a `corpusRole`. Neither is mentioned, so the first contact is a gate failure.
4. **DSL 2.0 is invisible.** A session could author a model using retired aliases and be confused by
   the rejection, with `BREAKING.md` unmentioned in that context.

**Where.** `CLAUDE.md` — the module map and the "Key docs" section.

**How to solve.** Add a short section; brevity matters more than completeness — CLAUDE.md's value is
that it is read in full:

```markdown
## Where the truth lives (read before filing or editing status)

- **Open items:** `ledger/items/*.yml` is authoritative. `docs/OPEN_ITEMS.md` is GENERATED from it
  (`scripts/quality/generate_open_items.py`) — never hand-edit. `docs/NPDEV_OPEN_ITEMS_REGISTER.md`
  is HISTORICAL/archived-in-place: read for narrative, never for status.
- **DSL is at 2.0** — 23 `flowStep.type` aliases collapsed to 12 canonical values. See `BREAKING.md`.
  Every breaking change ships its codemod (`NPDevCli/dsl_v2_migration.py`) in the same commit.
- **Adding a DSL feature?** Add an example to `NPDevSamples/dsl-conformance-max` in the same commit —
  the coverage gate enforces it.
- **Adding a script under `scripts/`?** Declare its `invocation` in
  `scripts/policy/script-invocation-declarations.json`; the inventory gate enforces it.
- **Adding a corpus model?** It needs a `corpusRole`; the corpus gate enforces it.
- **Frontend contract:** `docs/UI_CONTRACT.md` · screen classes: `docs/SCREEN_TAXONOMY.md` ·
  the durable flow engine: `docs/FLOWS.md`.
```

**Definition of done.**
- [ ] CLAUDE.md names the ledger as authoritative and the register as historical
- [ ] All three "adding X requires declaring Y" rules are stated
- [ ] DSL 2.0 + `BREAKING.md` + the codemod rule are stated
- [ ] `FLOWS.md`, `UI_CONTRACT.md`, `SCREEN_TAXONOMY.md` reachable from CLAUDE.md
- [ ] The file still reads end-to-end in one pass — if the addition makes it sprawl, trim elsewhere

## P4 ★ · A detector for the two undetected record surfaces

**What.** P1, P2 and P3 are three instances of one class: *a surface of record goes stale after
successful work, and nothing notices.* Four earlier instances already have detectors (Rule T1, Rule
T2b, T4's deferral rule, the drift checker). **Branch state and CLAUDE.md are the two surfaces no gate
reads** — and they are the two a stranger meets first.

**Why it matters.** Without this, P1 recurs a fourth time and P2/P3 recur the next time a large file
is split or a system is added. The last engagement's lesson was that fixing instances one at a time
produced four discoveries of the same shape over three weeks; the class fix ended it.

**Where.** New `scripts/quality/check-record-surfaces.py`, wired into the knowledge gate.

**How to solve.** Two cheap, static assertions — no new infrastructure:

1. **Branch freshness** (P1's detector, folded in): warn >20, fail >50 commits ahead of
   `origin/main`.
2. **CLAUDE.md size claims:** parse every `` `path` (N KB) `` in the large-files block and compare to
   the file on disk. Fail when a claim is off by more than ~25%, or when a listed path no longer
   exists. This alone would have caught both P2 misstatements the day the splits landed.

Deliberately **not** attempted: verifying CLAUDE.md's prose is complete. That is unbounded. The two
mechanical claims — sizes and branch gap — are the ones that go stale silently and can be checked
statically.

**Calibrate:** point it at CLAUDE.md as it stands today (pre-P2) and confirm it fires on
`TrustedSourceEmitter` and `SemanticValidator`; fix P2 and confirm green. That is a free real fixture
— capture it **before** P2 lands, exactly as the corpus gate's RED run was captured before migrating.

**Definition of done.**
- [ ] Both assertions implemented and wired blocking
- [ ] Calibrated RED against today's CLAUDE.md and a synthetic 51-commit gap; GREEN after P1/P2
- [ ] A file split that leaves a stale size claim fails the build

**Why it matters.** It is now the largest under-tested surface in the repo, and unlike the backend it
has no compiler catching structural mistakes. It is also the **authoring front door** — ADR-0006
ratified AI-first authoring, but a human evaluator who opens the editor meets this code first.

Mitigating: it *is* in the PR gate now (F/T-series work), the 32 unreachable panels are gone, and
`ImportExportWorkspace` / `previewManifest` are the two whose breakage would be most visible.

**Where.** `NPDevEditor/ui-react/src/authoring/`.

**How to solve.** Do **not** attempt broad coverage — it is 15 k LOC and mostly UI. Target the two
modules with real logic and real blast radius:

1. **`previewManifest.ts`** — pure-ish logic, easiest to test, feeds what the user sees.
2. **`ImportExportWorkspace.tsx`** — round-trip a model in and out; a regression here silently
   corrupts a user's model, the worst failure mode in the editor.

A round-trip test (import a known model → export → assert byte-equality) is one test with
disproportionate value, and mirrors `editorRoundTripAndUx.test.ts`'s existing shape.

**Definition of done.**
- [ ] `previewManifest.ts` and `ImportExportWorkspace.tsx` have unit tests
- [ ] A model round-trip is asserted byte-identical
- [ ] Editor vitest still runs per-PR and stays under its 10-minute cap
